# AI 医助小南 v2：流程嵌入与交互设计

## 1. 体验命题

### 1.1 从“先选 Agent”改为“先选诊疗任务”

当前交互把 Agent 当成应用入口，临床用户需要理解 Agent 名称、边界和版本后才能开始。目标交互改为：

```text
当前页面与诊疗阶段
→ 展示 1–3 个可完成的任务
→ 自动匹配唯一主 Agent
→ 预览数据范围与执行步骤
→ 运行并展示可理解的子任务进度
→ 交付来源化候选
→ 人工复制、修改、拒绝或进入原业务审批
```

主 Agent 是任务责任标识，不是用户必须先理解的技术选择器；子 Agent 是可独立失败和追踪的运行单元，不是首页菜单。

### 1.2 五条界面原则

1. **任务优先：** 主按钮用“生成今日查房病程”，不用“运行 DocumentDrafter”。
2. **路由可解释：** 开始前说明“匹配到哪个主 Agent、为什么、读取什么、将做几步”。
3. **协作可感知、过程可接管：** 展示参与本任务的子 Agent、可观察动作、贡献和接力；始终提供停止和转人工，不展示隐藏思维链。
4. **结果可回源：** 关键事实、冲突和缺失项可定位来源；来源不可用时不得伪装已验证。
5. **候选不越权：** 主动作最多到人工草稿或动作审批，签署/执行仍在原业务状态机。

## 2. 界面层级

| 层级 | 界面 | 何时使用 | 不承担 |
|---|---|---|---|
| S0 | 顶栏小南入口 | 任意桌面页面唤起；显示上下文/未读 | 不直接执行临床任务 |
| S1 | 流程内“本环节可协助”任务条 | 页面已有明确诊疗阶段 | 不展示全部 Agent、Skill、Tool |
| S2 | 非模态右侧任务面板 | 路由确认、短任务、执行进度 | 不覆盖保存、签署、患者身份和主任务 |
| S3 | 完整任务工作台 | 多步骤、子 Agent 协作、长内容、来源审阅、恢复 | 不替代原临床工作台 |
| S4 | 来源/差异抽屉 | 核验事实、冲突、文书差异 | 不长期占用第三栏 |
| S5 | 独立动作审批页 | T3 副作用或现有业务动作 | 不在小南面板内一键批准 |

桌面只保留顶栏为永久入口。右下角只在存在时效性提醒时出现可关闭 Nudge；关闭后不留下第二个永久 FAB。该项为 `INFERRED`，需产品确认。

## 3. 核心任务流

### 3.1 FLOW-XN-01 流程内发起

1. 用户进入患者/就诊/文书/结果/任务页面。
2. 页面根据业务状态显示最多 3 个“本环节可协助”任务。
3. 用户选择任务，右侧面板展示：当前患者/就诊、主 Agent、匹配原因、数据范围、执行步骤、候选类型。
4. ContextLease 尚未建立时显示加载；无权、过期或多患者请求时阻断，不展示敏感存在性。
5. 用户点击“开始生成”；系统创建唯一 root run。
6. 面板显示人类可理解的步骤状态；可停止、转人工或打开完整工作台。
7. 结果完成后在原页面显示候选摘要和主动作；完整内容进入 S3/S4。

### 3.2 FLOW-XN-02 自然语言发起

1. 用户从顶栏打开小南并描述任务。
2. 小南先识别任务，不直接显示 Agent 目录。
3. 高置信且单一目标时展示路由确认卡。
4. 环节、患者或目标不明确时，只问一个最小澄清问题。
5. 用户确认后进入与 FLOW-XN-01 相同的 root run。

### 3.3 FLOW-XN-03 审阅候选

1. 结果头部显示候选类型、主 Agent、完整性、来源覆盖、未决项和失效条件。
2. 用户可在正文中逐段打开来源；冲突来源并列，不由 UI 自动消解。
3. 文书类提供“对比当前草稿”和“复制到人工草稿”；摘要类提供“复制摘要”或“带入当前任务”。
4. 若 `partial=true`，所有动作前持续显示缺失范围；是否允许复制由 Q-006 决定。
5. 接受/复制不等于签署、处方生效、任务完成或危急值处置。

### 3.4 FLOW-XN-04 失败与恢复

1. 关键步骤失败：显示“已阻断”、失败阶段、已完成范围、人工替代路径。
2. 非关键步骤失败且组合允许：显示“部分完成”和缺失范围，禁止使用绿色成功样式。
3. 患者/就诊/岗位变化：旧面板立即进入 `EXPIRED/BLOCKED`，正文折叠并清除可执行动作。
4. 副作用结果未知：进入 `RECONCILING`，只提供核验状态和返回人工流程，不提供盲重试。
5. 用户恢复时创建新 run；旧轨迹只读保留。

## 4. 主 Agent 在 UI 中的表达

| 主 Agent | 用户名称 | 语义标识 | 典型任务 | 结果骨架 | 禁止主动作 |
|---|---|---|---|---|---|
| `ENCOUNTER_SUMMARIZER` | 就诊摘要 | 蓝色文档图标 + “就诊摘要” | 诊前摘要、近 24 小时、出院准备 | 事实、变化、未闭环、待确认、来源 | “确认诊断”“批准出院” |
| `DOCUMENT_DRAFTER` | 文书草拟 | 紫色羽笔图标 + “文书草拟” | 门诊病历、病程、查房、出院、交班 | 结构化候选、段落来源、缺失项、差异 | “自动签署”“覆盖原文” |
| `RECORD_QC` | 病历质控 | 琥珀盾牌图标 + “病历质控” | 书写中、签署前、运行/终末质控 | 硬规则、AI 发现、证据、严重度建议、整改方向 | “自动豁免”“降低硬规则” |
| `RESULT_FOLLOWUP_COORDINATOR` | 结果闭环 | 青色闭环图标 + “结果闭环” | 新结果、趋势、待回、更正、随访任务 | 结果版本、趋势、状态、未闭环责任、任务候选 | “已通知”“已处置”“自动治疗” |
| `CARE_COORDINATOR` | 诊疗协同 | 绿色协作图标 + “诊疗协同” | 会诊、MDT、转科、出院、随访、任务对账 | 目标、资料、责任、时限、接收状态、动作候选 | “交接完成”“自动发送/改约” |

颜色只用于辅助分组；每处必须同时显示图标和文本。红色只保留给硬阻断/危急语义，不作为 Agent 品牌色。

## 5. 子 Agent 可见性

完整的 33 个子 Agent 用户角色、卡片和贡献契约见 [子 Agent 协作体验设计](./child-agent-experience.md)。子 Agent 在 v2 中不是匿名步骤，而是可见但受控的协作者。

### 5.1 默认层

临床用户首先看到带角色名的协作步骤：

```text
✓ 住院每日摘要协作员 · 已完成 · 提供 6 条来源事实包
● 查房记录草拟员 · 协作中 · 正在整理查房记录
○ 独立核验环节 · 非子 Agent · 等待核验来源与冲突
○ 文书草拟主 Agent · 等待聚合并交付人工审阅
```

默认显示中文角色名；`INPATIENT_DAILY_SUMMARIZER` 等 code 在技术详情折叠。不显示模型思维链、Prompt 或原始 Tool payload。

### 5.2 展开层

“查看 Agent / Skill / Tool 详情”抽屉展示：

- 主 Agent 展示名、code、release version、责任 owner。
- 每个子任务的人类名称、Agent code/version、关键/非关键、状态、耗时。
- Skill 名称/version；Tool 只显示类别、风险级和调用结果，不展示秘密或原始 PHI。
- 模型路由只显示批准的 provider/model、数据驻留标签和 fallback 是否发生。
- root/parent/run ID 可复制给支持人员；默认不在临床正文出现。

### 5.3 高风险与失败强制展开

以下情况自动展开相关步骤，不自动展开全部技术细节：

- 关键子 Agent `BLOCKED/FAILED`。
- 非关键子 Agent 失败导致 `PARTIAL`。
- Tool 被拒绝、审批过期、结果未知或 ContextLease 失效。
- 来源冲突、患者范围不一致或输出验证失败。

## 6. 诊疗环节嵌入矩阵

| 诊疗环节/页面 | 推荐任务条 | 默认主 Agent | 主要步骤/子 Agent | 入口位置 | 完成后的落点 |
|---|---|---|---|---|---|
| 预约后/诊前准备 `appointment-registration` | 生成诊前摘要；列出待核问题 | 就诊摘要 | PreVisit | 患者预约详情右侧任务区 | 诊前准备卡，不写病历 |
| 门诊分诊/急诊预检 `er-triage` | 汇总分诊上下文；检查资料缺失 | 就诊摘要 | TriageContext | 分诊事实下方 | 分诊摘要；定级仍由规则/人工 |
| 门诊接诊 `outpatient/opd-record` | 总结本次就诊；生成门诊病历；签署前检查 | 就诊摘要 / 文书草拟 / 病历质控 | ActiveEncounter、OutpatientDraft、PreSignQC | 病历编辑器上方任务条 | 摘要、人工草稿或质控清单 |
| 诊断形成 `opd-diagnosis` | 核对现有证据；检查术语一致性 | P1 诊断复核，P0 不默认启用 | P1 预规划 | 诊断候选区 | 仅候选/缺口，不确诊 |
| 医嘱/处方 `opd-orders` | 解释硬规则；生成用药交代草稿 | P1 安全复核，P0 不默认启用 | P1 预规划 | 规则结果之后 | 解释/草稿，不生效 |
| 执行与床旁观察 `inpatient-overview` | 总结近 24 小时；对账未完任务 | 就诊摘要 / 诊疗协同 | InpatientDaily、TaskReconciliation | 查房概览顶部 | 查房摘要、任务差异 |
| 新结果/危急值 `opd-results/ip-results` | 解读趋势；查看未闭环；核对更正影响 | 结果闭环 | NewResult、Trend、CriticalContext、CorrectedResult | 结果列表选中项侧面板 | 结果摘要/任务候选，状态不被覆盖 |
| 住院查房/病程 `inpatient-course` | 总结近 24 小时；生成病程；生成查房记录 | 就诊摘要 / 文书草拟 | InpatientDaily、ProgressDraft、WardRoundDraft | 查房任务条 | 文书人工草稿 |
| 会诊/MDT/转科 `ip-consult` | 准备会诊摘要；生成交接；对账任务 | 诊疗协同 / 文书草拟 | ConsultPreparation、MDTBrief、TransferHandoff、ConsultDraft | 会诊/转科任务页 | 协同候选或文书草稿 |
| 围手术期 `surgery-schedule` | 汇总围术期资料；草拟指定记录 | 就诊摘要 / 文书草拟 | PerioperativeContext、PerioperativeDraft | 核查清单之后 | 事实包/候选；核查事实不可代填 |
| 出院准备 `inpatient-discharge` | 检查出院准备；生成出院小结；生成连续照护计划 | 就诊摘要 / 文书草拟 / 诊疗协同 | DischargeReadiness、DischargeNote、DischargeTransition | 出院核对顶部 | 未闭环清单、文书/计划候选 |
| 随访与结果追回 `opd-followup` | 列出待回结果；生成随访任务；对账任务 | 结果闭环 / 诊疗协同 | PendingResult、FollowupTask、FollowupCoordination | 随访计划区 | 任务/提醒候选，红旗转人工 |
| 书写中/签署前 `record-editor/record-sign` | 检查当前草稿；对比来源；生成缺失段落 | 病历质控 / 文书草拟 | WritingQC、PreSignQC、对应 Drafters | 编辑器工具条，不遮挡签署 | 质控清单/人工草稿 |
| 运行/终末/更正质控 `record-qc` | 运行质控；终末质控；检查更正影响 | 病历质控 | ActiveQC、TerminalQC、CorrectionConsistency | 质控任务详情 | 缺陷候选；正式关闭仍人工 |

同一页面可展示多个任务，但一次运行只有一个主 Agent。若用户连续选择另一主 Agent 的任务，创建新 root run，不把两个主 Agent 混在同一执行计划中。

## 7. 核心屏幕规格

### XN-001 顶栏统一入口

- 尺寸：高度 36px，图标 24px，文字“AI 医助小南”；最小点击区 44×44px。
- 上下文正常：无状态点；有高优先未读任务时显示数字，最大 `9+`。
- 无患者：打开 XN-002；不显示患者相关建议数量。
- 患者切换：入口短暂显示“上下文更新中”，旧面板动作立即禁用。
- 桌面不同时放置永久右下 FAB。

### XN-003 “本环节可协助”任务条

- 位于主业务对象之后、编辑/操作主体之前，不插入患者身份条。
- 最多 3 个主要任务；更多任务进入“查看全部可用任务”。
- 每项为“动词 + 对象”，附 1 行效果说明；不显示版本号。
- 页面没有批准用例时整条不显示，不放置灰色不可用噪声。
- AI 停用时显示单行“AI 当前不可用，不影响人工流程”，不改变主页面布局。

### XN-004 路由确认卡

固定字段：

1. 当前任务。
2. 已匹配主 Agent + 人类名称。
3. 匹配原因：页面、业务状态、用户目标。
4. 数据范围：患者/就诊、时间窗、对象类型。
5. 将执行的步骤数量和候选类型。
6. 禁止动作与失效条件。

动作：`开始生成`、`更换任务`、`取消`。不提供“继续使用未知 Agent”。

### XN-005 流程内右侧面板

- 标准宽 420px；≥1600px 可到 480px；低于 1280px 转为 560–720px 非模态抽屉。
- 必须通过布局重排让出空间，不能盖住保存、签署、确认、患者身份或关键结果。
- 面板头部固定上下文、候选制和关闭；底部固定当前可用动作。
- 执行过程中原页面可操作，但关键对象变化会使运行过期并立即提示。

### XN-007 完整任务工作台

- 顶部：患者/就诊/任务 Context Strip，严重风险仍来自临床内核。
- 主区 8 列：任务目标、结构化候选、来源 chips、缺失/冲突、审阅动作、任务输入。
- 右轨 4 列：执行计划、耗时、关键性、技术详情、停止/接管。
- 来源与差异使用抽屉或全宽模式；不恢复为长期三栏。
- 聊天记录降级为“任务补充说明”，不占据首屏主体。

### XN-008 来源审阅

每条来源展示：来源对象、时间、版本、原文定位、授权状态、取数时间、是否更正。冲突按来源分组并列；不可用来源显示具体原因，不显示无权对象的敏感标题。

### XN-009 文书差异审阅

- 左侧当前人工草稿，右侧 AI 候选，或使用逐段 inline diff；两者不能同时在窄侧栏中展示。
- AI 新增为紫色细边与“AI 候选”，删除建议用删除线和文本标识；硬规则使用独立红/琥珀区。
- 每段提供来源、未决项和“复制本段”；批量复制前再次显示 partial/stale 状态。
- 不提供“全部接受并签署”。

### XN-010 动作审批交接

小南仅展示动作预览摘要和“进入审批”。独立审批页必须完整呈现患者、对象、参数、证据、风险、payload hash、有效期、后果和恢复方式。返回后小南显示真实审批/执行/对账状态。

### XN-014 运行历史

- 以 root task 为一行：任务名、主 Agent、患者/就诊安全标签、发起人、开始时间、终态、proposal。
- 展开后展示 child 步骤；不把每个子 Agent 当成独立历史主行。
- 可恢复只在授权、水位、release graph 和输入未变化时出现；否则显示“以新任务重新运行”。

## 8. 文案系统

### 推荐

- “根据当前页面与诊疗阶段，已匹配：文书草拟”
- “将读取：当前就诊 + 近 24 小时授权资料”
- “任务部分完成：结果趋势不可用，其余摘要已生成”
- “患者上下文已变化，本次任务已停止”
- “复制到人工草稿后仍需按原流程审阅与签署”

### 禁止

- “AI 已诊断”“AI 已处置”“AI 已完成交接”
- “一键自动写入/签署/开药”
- “选择最聪明的 Agent”
- “100% 准确”“已验证安全”
- 用“成功”描述仅生成候选的状态；应使用“候选已生成，等待人工审阅”。

## 9. 响应式与缩放

| 条件 | 布局 |
|---|---|
| ≥1600px | 业务页 + 480px dock；完整工作台 8/4 |
| 1280–1599px | 业务页 + 420px dock；部分次要列折叠 |
| 1024–1279px | 右侧面板转 560–720px 抽屉；打开时主页面仍可水平无溢出 |
| 200% 缩放 | 单列任务页；执行计划置于候选之前；固定动作改为普通流式区 |
| prefers-reduced-motion | 路由/步骤变化使用即时状态切换，无脉冲和位移动画 |

长任务名最多两行；步骤描述最多三行后展开；Agent code 和版本在技术详情中允许等宽换行。
