# 子 Agent 协作体验设计

> - 状态：`CREATED`
> - 范围：P0 5 个主 Agent 下的 33 个候选子 Agent
> - 目标：让医生明确感知“谁正在协助、正在做什么、贡献了什么、哪里没有完成”，同时保持主 Agent 对最终结果负责

## 1. 设计结论

子 Agent 不再仅显示为匿名步骤，但也不设计成彼此聊天的虚拟医生团队。用户感知采用“**协作角色卡 + 接力关系 + 贡献凭证**”：

```text
主 Agent（任务负责人）
  ├─ 子 Agent A（独立协作目标、当前动作、输入范围）
  │    └─ 贡献：事实包 / 候选段落 / 发现 / 任务计划
  ├─ 交接：输出已传给下一位协作者
  └─ 子 Agent B（独立协作目标、当前动作、贡献）
       └─ 主 Agent 聚合 → 独立核验 → 人工审阅
```

用户在四个时刻能感知子 Agent：

1. **开始前：** 看见本次会由哪几位子 Agent 接力，以及各自读取什么。
2. **执行中：** 看见每位协作者的可观察动作、状态、来源数量和接力关系。
3. **结果中：** 每个关键段落带“由谁贡献”的凭证，可查看来源和边界。
4. **失败时：** 明确是哪位协作者未完成、缺失影响什么、主任务为何 partial/blocked。

## 2. 信息架构

### 2.1 `ChildAgentCollaborationRail`

完整任务工作台右轨顺序：

1. 主 Agent Leader Card：任务负责人、最终责任、聚合状态。
2. Child Agent Collaborator Cards：按 DAG 顺序展示；并行节点并排/同组。
3. Handoff Connector：只显示“事实包已交接、候选已交接、等待上游”等结构化事件。
4. Independent Verification Card：明确写“非子 Agent”，避免误算为协作角色。
5. 停止任务、转人工、技术详情。

侧面板空间有限时仅展示“当前协作者 + 上一位贡献 + 下一位等待”，其余折叠为“另有 N 位协作者”。

### 2.2 `ChildAgentCard`

| 区域 | 必填内容 |
|---|---|
| 标题 | 中文角色名 + 功能图标，不使用人类头像 |
| 归属 | “就诊摘要主 Agent 的协作者”等父级关系 |
| 状态 | 图标 + `准备中/协作中/已完成/未完整/无证据/已阻断/失败/已取消` |
| 当前动作 | 可观察动作，如“正在读取近 24 小时结果与医嘱”，不用“思考中” |
| 输入范围 | 数据类别、时间窗、来源数；无权内容不泄露 |
| 贡献 | 事实包、候选段落、发现、清单或任务计划的数量/摘要 |
| 动作 | 查看贡献、查看来源；策略允许时可重新运行此协作者 |
| 技术详情 | code、version、Skill、Tool、run lineage，默认折叠 |

### 2.3 `ContributionBadge`

关键结果段落旁显示：

- `住院每日摘要协作员 · 提供事实包 · 6 条来源`
- `查房记录草拟员 · 生成候选段落`
- `签署前质控员 · 发现 2 项需核验`
- `更正结果对账员 · 标记 3 个受影响对象`

点击后打开贡献抽屉：子 Agent 输入摘要、结构化输出、来源、版本、完成状态和主 Agent 如何使用该贡献。不得展示隐藏思维链。

### 2.4 接力文案

允许：

- “事实包已交给查房记录草拟员”
- “等待住院每日摘要协作员完成”
- “候选已返回文书草拟主 Agent 聚合”
- “此协作者未完成；主任务缺少结果趋势部分”

禁止：

- “两个 Agent 正在讨论患者”
- “子 Agent 认为医生应该……”
- “正在深度思考/推理”
- “子 Agent 已完成诊断/处置/交接”

## 4. 子 Agent 状态

| 内部结果 | 用户状态 | 卡片表达 | 主任务影响 |
|---|---|---|---|
| `CREATED/QUEUED` | 准备中 | 灰蓝空心图标，“等待上游/等待开始” | 无 |
| `RUNNING` | 协作中 | 蓝色 active ring + 具体可观察动作 | 可停止/转人工 |
| `COMPLETE` | 已完成 | 绿色勾 + 贡献摘要 + 查看贡献 | 进入下一接力 |
| `INCOMPLETE` | 未完整 | 琥珀图标 + 已完成/缺失范围 | 按 criticality partial/blocked |
| `NO_EVIDENCE` | 无足够证据 | 灰蓝信息图标 + 已检查范围 | 不伪造输出 |
| `BLOCKED` | 已阻断 | 红色停止图标 + 解除条件 | 关键节点阻断主任务 |
| `FAILED` | 失败 | 红色错误图标 + 安全重试/人工路径 | 按组合策略处理 |
| `CANCELLED` | 已取消 | 灰色取消图标 + 取消来源 | 禁止晚到结果恢复 UI |

“已完成”仅表示子任务契约完成，不表示诊断、签署、执行或任务终态完成。

## 5. 用户控制

| 动作 | 是否允许 | 条件 |
|---|---|---|
| 查看子 Agent 当前工作 | 允许 | 只展示结构化活动和来源数量，不展示思维链 |
| 查看子 Agent 贡献 | 允许 | Scope 内实时鉴权；来源不可用时显式说明 |
| 重新运行某个子 Agent | 条件允许 | 只读、输入未变、组合声明可重试；创建新 child run |
| 跳过非关键子 Agent | 条件允许 | 组合预先允许；开始前展示结果会缺失什么 |
| 直接给子 Agent 下自由指令 | 默认不允许 | 用户意图仍由主 Agent 接收，避免目标和权限漂移 |
| 更换子 Agent 实现 | 不允许 | 生产只使用批准的 Composition Release |
| 接受子 Agent 输出为临床事实 | 不允许 | 必须经主 Agent 聚合、独立核验和人工审阅 |

## 6. 可访问性与内容规则

- Child card 最小高 104px；标题、状态、当前动作和贡献顺序固定。
- 并行子 Agent 使用同级分组，不用仅靠横向箭头表达顺序。
- 屏幕阅读器示例：“查房记录草拟员，步骤 2/2，协作中，正在将事实包整理为查房记录”。
- 连接线不是唯一的接力信息，必须有“事实包已交接”等文本。
- 侧面板最多展开 3 张卡；更多卡使用摘要列表，完整工作台展示全部。
- 不为 33 位子 Agent 生成不同人物头像；统一功能图标保证专业性与可维护性。
