# AI 中心生产化增量整改与验证报告

- 日期：2026-08-31（Asia/Shanghai）
- 范围：AI 中心一级菜单、全部可见二级菜单、相关三级及更深管理页、医疗医助运行时、模型服务、评测、安全和运行证据
- 对照基线：`2026-08-31-s009-pc-full-functional-s010-security-report.md`
- 结论：**NO_GO（生产） / GO（受控合成环境与影子验证）**

## 1. 结论

本轮没有把“页面可点击”当成完成。已完成的部分均已连接真实 API、数据库记录或真实模型调用，并有定向测试证据；仍未形成生产闭环的部分列在第 6 节，不能计入完成率，也不能据此宣布 AI 中心已生产就绪。

本轮消除了以下已知演示或高风险实现：

1. Eva 输入框缺少可访问名称。
2. AI 总览把示例模型当成正常服务展示。
3. 模型连接、模型路由、AI 运行证据采集使用仿真工作台。
4. 云端/境外 Provider 只有前端开关、没有数据处理授权记录和运行时门禁。
5. 医助运行只保存单次模型调用，看不到真实模型、工具、Token、耗时和失败证据。
6. 医助工具固定写死且返回拼装摘要，未按已发布依赖读取临床数据库。
7. Eva 工作策略只在配置页存在，运行时不固定版本、不校验来源、环境、医生确认和调用频率。
8. 管理员手工填写模型评测分数后自动把模型置为 `APPROVED`。
9. 三级医院 AI 仿真模型和已被真实页面替换的仿真工作台仍处于启用口径。

## 3. Agent、Tool 与模型运行整改

### 3.1 真实 Agent 运行

- 医助运行必须选择处于 `ACTIVE + APPROVED + READY` 的模型部署。
- 运行记录保存模型部署、Provider、请求次数、输入/输出/总 Token、真实耗时和最终状态。
- 云模型运行必须存在有效的数据处理授权，且覆盖本次上下文范围；撤销、过期或范围不足均失败关闭。
- 创建任务固定已发布 `AI_ASSISTANT_POLICY` 的配置 ID、版本、哈希和环境；Worker 再次核对，防止排队期间策略漂移。
- 策略门禁覆盖医生确认、环境、模型策略、允许数据来源、5 主/33 专科医助拓扑和调用频率。
- 运维接口按机构/院区隔离，管理页不返回患者标识。

### 3.2 已接通的真实工具适配器

当前主医助已发布依赖可执行的适配器包括：生命体征、检验趋势、手术排程、麻醉记录、院感事件、护理记录、病理报告、影像报告、MDT、用药执行、就诊时间线、病历模板、质控规则、危急值和会诊记录；通用受控读取还覆盖病历、医嘱、结果、任务、附件和业务配置。

工具网关按医助已发布依赖和上下文授权选择工具；缺少适配器时明确失败，不再返回伪造成功结果。每次调用保存工具版本、结果、数据项数量、耗时和错误码。

### 3.3 模型评估安全修复

手工评测分数仍可作为不可变证据记录；通过后模型状态现在为 `EVALUATING`，不会自动进入 Eva 路由。未通过仍立即置为 `REJECTED`。该改动修复“管理员手填分即上线”的风险，但独立发布审批 API 尚未完成，因此生产结论保持 NO_GO。

## 4. 中国医疗生产环境适配

- 用户界面统一使用“医助、医助团队、专科医助、医助能力、医助工具、医生确认”等术语，不向医生暴露 Harness、ContextLease、候选制或主/子 Agent 等工程术语。
- 云模型授权记录包括合法性基础、个人信息保护影响评估编号、受托处理协议编号、处理地域、保留天数、允许数据范围、有效期、撤销人和撤销原因。
- 运行时采用最小必要数据范围；跨患者、患者/就诊变化、授权范围不足和数据处理审批缺失均失败关闭。
- 管理监测不显示患者身份；审计证据使用哈希链；临床写入仍要求医生独立确认。
- 示例数据明确为三级甲等医院合成数据；示例模型全部停用，只有管理员真实配置并通过连接/评测门禁的模型可运行。

## 7. 发布判定

- 合成环境功能开发和受控影子验证：**GO**。
- 接入真实患者数据前的院内试点：仅在院方完成数据处理审批、账号与职责分离、模型正式评测并保持只读/人工确认的条件下可申请受控试点。
- 自动执行临床写入或直接生产发布：**NO_GO**。

下一批必须按顺序完成：模型双人发布审批 → 新运行与临床操作执行台账统一 → Context/Composition 运行时权威化 → Skill Adapter → 补齐剩余工具适配器 → 20+ 真实模型评测与临床专家复核 → AI 中心全页面浏览器视觉回归。
