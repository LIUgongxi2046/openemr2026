# R01-T3 病历自动保存、加密恢复与并发冲突验证报告

> 日期：2026-08-20  
> 结论：`LOCAL_VERIFIED`；R01 总任务仍为 `IN_PROGRESS`

## 已交付能力

- 停止输入 800ms 自动保存，连续输入最长 5s 触发；同一时刻只允许一个保存请求，保存期间的新编辑不会被旧响应覆盖。
- 输入法组合期间不保存；存在未提交内容时离开页面触发浏览器原生保护；质控和签署在未保存、冲突或失败状态下禁用。
- 会话草稿使用 WebCrypto AES-GCM 加密后写入 IndexedDB，密文以存储标识作为附加认证数据，并绑定租户、患者、就诊和文书的 SHA-256 伪匿名上下文指纹。
- 页面重新进入时只恢复同一上下文、同一会话的草稿；上下文不符、密文损坏、选择丢弃或文书签署后清除。
- 服务端仍以不可变病历版本和 `expected_row_version` 乐观锁为准。冲突不自动合并、不覆盖本地正文，医生可逐字段选择本地或服务器版本，并打开完整服务端 diff。
- 浏览器存储不可用时失败关闭：界面明确显示加密草稿不可用并停止自动保存，不把未持久化内容误报为已保存。

## 真实端到端证据

1. 创建合成草稿 v1，在 `#/opd-record` 编辑主诉，自动保存为 v2，页面显示“已自动保存”。
2. 通过本机合成 API 模拟另一工作站基于 v2 保存服务器 v3；原页面继续编辑时收到版本冲突，本地字段和服务器字段同时可见，系统禁止覆盖。
3. 选择“基于当前版本继续”后，以 v3 为新基线提交本地选择，生成不可变 v4，本地正文完整保留。
4. 在开发专用 5000ms 延迟实例中，编辑后立即切换路由；返回病历页时服务器仍为 v6，页面出现未提交加密草稿恢复入口。恢复后手工保存生成 v7，恢复提示清除。
5. 实测发现 Vue 响应式代理不能直接 `structuredClone`，会导致状态卡在“保存中”；现改为按病历 JSON 契约先生成无代理快照，并新增代理快照回归测试。

## 边界

- 会话密钥位于浏览器 `sessionStorage`，用于标签页会话隔离，不替代 CSP、XSS 防护、终端磁盘加密或医院统一终端管理。
- 浏览器真实断网的系统级网络切换未在本轮工具能力中执行；离线状态机与安全草稿路径已实现，密文、恢复和服务失败分支已通过单元/浏览器组合验证。后续移动护理离线场景仍需在真实终端进行断网、崩溃和多标签压力测试。
- R01-T4 更正链与签名撤销、R01-T5 住院四角色浏览器 E2E 尚未完成，因此不得宣称 R01 或 V1.0 已完成。
