# R01-T5 住院病历四级审签设计验收

> 日期：2026-08-20  
> 页面：`#/inpatient`、`#/inpatient-doc-editor`、`#/inpatient-doc-qc`  
> 结论：`PASS`（本机合成数据）

## 1. 信息架构

- 住院工作台负责患者、床位、规则任务和临床事件；病历编辑页只承载单文书创作、质控和审签，避免病历核心区域继续拥挤。
- 文书正文居左，质控动作和不可变证据居右；患者条、版本状态、当前岗位和四步进度在操作前可见。
- 创建入口收口到规则任务，不保留脱离时限、模板和签名策略的通用“新建文书”。

## 2. 临床安全交互

- 非当前岗位只能查看，不显示可误触的签署动作；完成态禁用填写、保存、质控和签署并显示闭环状态。
- WARNING 与 PASSED 不混同，WARNING 必须填写人工处置意见；BLOCKED 不能签署。
- 四份签名展示岗位、人员、时间、证据状态和同一内容哈希；CA 未接入时不使用“有效签名”文案。

## 3. 视觉与响应式

- 采用既有深蓝导航、蓝色主动作、绿色完成、琥珀警告语义，不新增平行视觉语言。
- 桌面采用正文双列与证据双栏；窄屏改为单列，角色和进度使用横向滚动，避免压缩字段和证据。
- 390px 复核未发现页面横向溢出；桌面复核未发现信息遮挡；全局 AI 助手保留固定入口且不覆盖主要按钮。

## 4. 浏览器结果

- 四角色真实请求链完成，最终 `v2 / SIGNED`、四步全部“证据已固化”、正文只读。
- 控制台：`0 error / 0 warning`。
- DOM 可访问性检查可定位一级导航、开发身份区域、患者上下文、四步进度、结构化字段、质控动作和签名时间轴。

## 5. 后续设计门禁

- 真实医院接入时移除开发身份区域，由登录主体和岗位任期决定当前角色；生产包安全扫描已覆盖此边界。
- 后续住院深页继续复用患者条、规则任务、右侧证据轨和统一状态色，不得重新堆回单一工作台。
