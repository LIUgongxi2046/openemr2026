# 住院工作台生产差距修复与定向回归报告

- 日期：2026-08-31（Asia/Shanghai）
- 模式：S008 IMPLEMENT + S009 EXECUTE/REPORT + S010 ASSESS/REMEDIATE
- 范围：住院授权、出院门禁、住院摆药、病区护理、住院 Agent 上下文
- 结论：**定向修复通过；整套产品仍为 NO_GO，不声明住院全模块已达到生产可用**

## 1. 本轮已修复

1. 生产授权由失败开放改为失败关闭：生产环境没有已发布的上下文授权策略时，拒绝签发租约和执行临床命令。
2. 生产职责分离落到服务端：护理写操作要求有效的注册护士/护士长岗位；药房操作要求有效药师岗位。开发合成环境保留兼容开关，生产配置强制开启。
3. 出院必需文书不得一键豁免：遗留请求即使携带豁免原因也不能绕过未完成/逾期文书门禁，且不再把待办改成 `WAIVED`。
4. 住院摆药必须关联当前住院就诊的已签署有效药品医嘱项；服务端校验患者、就诊、机构、医嘱状态、项目类型、药品编码、单位及累计摆药量，并对医嘱项加锁防止并发超量。
5. 住院药房页面取消自由录入药品编码和单位，改为从有效药品医嘱选择；来源医嘱项在台账显示。新增、编辑、核验、发药、作废继续使用弹窗。
6. 病区护理页由“交接班展示页”扩展为可写工作台：接入住院生命体征、护理计划创建、完成评价和终止流程，全部使用弹窗和住院上下文 API。
7. 住院药房打开 Eva 时改为携带当前住院患者和住院就诊，不再错误降级成机构级 Agent 上下文。
8. 浏览器验收脚本同步到新摆药契约：必须选择有效医嘱，不再尝试填写只读药品编码和单位。

## 3. 仍未完成，禁止宣称生产可用

1. **真实 CA/TSA 电子签名**：当前生产启动会校验 CA、时间戳和密钥引用，但临床文书签名链尚未证明真正调用医院 CA/TSA 并验证证书吊销、时间戳和长期验签。
2. **住院退药和库存批次闭环**：已发药记录会阻止直接作废，但独立的退药申请、药师验收、可再入库/销毁判定及库存批号增减尚未实现。
3. **LIS/PACS 深度闭环**：住院结果页已有结果和危急值能力，但住院菜单内尚未完整覆盖标本条码/拒收/重采、影像预约准备、检查执行、DICOM accession 和报告签发全链。
4. **中国病案首页与医保口径**：出院门禁可影响床位和在院状态，但国家病案首页字段、主诊断/主手术选择、编码质控、医保结算清单和首页上报校验尚未形成完整闭环。
5. **护理生产要素**：本轮完成生命体征、护理计划和既有交接班；入出量、压疮/跌倒/VTE 风险量表、管路、输液巡视、护理级别与护理文书审签仍需补齐。
6. **药房以外的岗位强制**：护士和药师写操作已服务端限制；检验、影像、病案编码、输血和手术等执行岗位仍需逐端点完成相同的生产强制验证。
7. **真实模型安全门禁**：Agent 运行、上下文、预算、工具调用和人工复核链在合成环境通过；真实模型制品、推理引擎、哈希、硬件及批准阈值仍未配置，不能宣称真实模型可上线。
8. **二至七级页面**：已有有业务意义的文书编辑、质控、版本证据等深层页面；尚不存在覆盖所有模块的六/七级业务对象页面。不能为了层级数字制造空路由，后续应按医嘱项、执行任务、标本、报告、会诊意见、护理计划、病案首页及审计证据等真实对象补齐。
9. **真实数据**：当前是三级医院业务口径的合成数据，不是也不应是未经授权的真实患者隐私数据。生产前仍需完成受控迁移、脱敏验证、数据质量和主数据对码。
10. **全量验收**：本轮住院专项浏览器链已通过，但只覆盖 5 个住院二/三级入口和摆药写链；必须在工作区冻结后跑全量 Java、全量 Web、全部住院菜单多角色写链和 S010 安全回归，才可改变 NO_GO 结论。
