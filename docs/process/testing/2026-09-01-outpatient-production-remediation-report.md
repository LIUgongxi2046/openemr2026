# 门诊工作台生产化整改与验证报告

- 执行时间：2026-09-01（Asia/Shanghai）
- 范围：门诊工作台、门诊病历、诊断、医嘱处方、检查检验结果、会诊转诊、随访终诊，以及关联的检验/影像执行和医疗 Agent
- 环境：`dev-synthetic`、PostgreSQL 18.4、Flyway V1–V323、Java 21、Vue 3
- 结论：**模块级合成环境验收通过；医院生产部署仍为 CONDITIONAL / NOT YET PRODUCTION-READY**

## 1. 本轮完成项

1. 门诊患者上下文改为用户绑定的持久上下文；切换患者时清理旧租约并按患者/就诊隔离查询缓存，退出登录时清理上下文。
2. 门诊终诊增加服务端闭环门禁：病历已签署、主诊断已确认、无草稿/校验中医嘱、无未接收或未处置危急值，满足后方可将就诊转为 `FINISHED`。
3. 诊断改为查询数据库中的有效 ICD-10-CN 版本，新增常见门诊疾病 2026B 术语数据；不再以前端硬编码假词典作为生产入口。
4. 医嘱、检验、影像、结果按中国三级医院职责分离：医生开立/签署，检验技师处理检验标本和检验结果，放射科医师执行影像和编写影像结果，护士执行护理/用药任务；服务端校验有效角色任期与机构范围。
5. 检验工作台补齐从标本采集、接收、拒收到完成执行任务的链路，使结果录入前置条件可达；影像工作台补齐执行与报告归档角色门禁。
6. 会诊转诊目标改为数据库科室，发送后生成真实临床任务，接受/拒绝要求独立处理人并结清任务；新增申请人与处理人审计字段。
7. 新建、编辑、停止/作废、完成/终诊等业务变更统一通过弹窗确认，删除采用可审计的业务生命周期而非物理删库。
8. 门诊 Agent 默认按当前路由选择病历起草、结果随访或照护协同能力；Agent 只生成候选内容，不能绕过确定性规则、审批和人工签署。
9. 修复中国时区凌晨候诊队列为空：日历型查询明确按医院时区 `Asia/Shanghai` 计算，不再使用 UTC `toISOString()` 截断日期，也不依赖终端自身时区。
10. 修复最新测试/安全报告中的门诊相关问题：AI 输入可访问名称、患者切换稳定选择器、独立执行角色数据、预约可选号源与无号源禁用、角色化结果录入验收脚本。

## 3. 仍未完成、不能宣称生产可用的部分

以下不是本轮已完成项，部署真实医院前必须继续建设和现场验收：

1. **真实外部系统联调未完成**：尚未用目标医院的 HIS/EMPI、医保、电子处方流转、合理用药、LIS、PACS/RIS、CA 电子签名、统一身份认证和消息平台完成端到端联调。
2. **真实模型门禁仍阻塞**：外部 DeepSeek 模型的制品哈希、推理引擎、硬件、批准阈值和真实模型红队未配置；当前通过的是 Agent 编排、权限、预算、审计和输出防护测试。
3. **外院转诊网络未接入**：院内目标科室和任务闭环已实现，外院目标仍为受控文本，未对接区域转诊平台或外院机构主数据。
4. **影像数据模型仍需收敛**：独立 `imaging_order` 与统一 `clinical_order`/结果域尚未完全合并；当前影像报告正文由结果工作台管理，影像工作台负责检查执行和报告归档状态。
5. **数据真实性边界**：当前数据是符合三级医院场景的高保真合成数据，不是真实患者数据。未获得合法授权、脱敏和审计条件前，不应把真实患者数据注入开发环境。
6. **非功能生产门禁未完成**：本轮没有重新完成目标医院规模下的并发性能、容量、双活/容灾、备份恢复、等保测评、渗透测试和医疗器械/院内软件合规判定。
7. **工程性能债**：生产构建仍报告主 bundle 超过 500 kB，需后续按路由拆包并做低配置终端首屏性能验收。

因此，本报告证明的是“门诊模块在隔离合成环境中的前后端业务闭环和角色安全边界已通过本轮验收”，不等同于“已经可直接部署到真实三级医院生产环境”。
