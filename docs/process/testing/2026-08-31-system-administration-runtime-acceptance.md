# 系统管理真实运行能力验收与安全修复报告

- 执行日期：2026-08-31（Asia/Shanghai）
- 范围：管理工作台、组织机构、用户账户、角色工作组、权限策略、认证安全、字典术语、主数据、模板输出、参数开关、通知任务、管理审计
- 环境：Vue PC Web、Spring Boot、PostgreSQL 18.4、`dev-synthetic` 三级医院合成环境
- 模块结论：**SYSTEM ADMINISTRATION PASS**
- 整系统发布结论：**NO-GO**（全量回归仍有 14 项非系统管理失败，详见“剩余问题”）

## 1. 本轮关闭的问题

1. 系统管理运行数据不再只依赖页面常量：补充主数据记录、工作组与成员、任务运行批次、治理问题等数据库表及真实 API。
2. 登录安全参数能够影响服务端行为：失败锁定、锁定分钟数、绝对/闲置会话时限、并发会话上限均读取已发布参数。
3. 参数与任务配置补充必填字段校验、作者/审批人真实角色校验和职责分离。
4. 通知任务由已发布配置进入数据库队列，支持领取、取消、失败/部分成功重试、批次对账和治理问题处置；“治理智能体”明确为可审计的确定性规则引擎，不冒充大模型。
5. 主数据按“目录版本 + 记录值”分层，记录支持新增、编辑、停用、国家/行业编码映射、有效期、乐观锁、幂等、审计和事务事件。
6. 角色目录与实际工作组分离；工作组支持创建、加人、退组和停用，仍有有效成员时禁止停用。
7. 用户账户支持真实角色任期分配，并增加人员档案 → 角色集合 → 任期详情 → 审计集合 → 单事件的多级下钻。
8. 管理审计查询新增服务端管理角色校验，普通临床角色不能仅凭页面入口读取管理审计。
9. 修复主数据默认目录强制筛选和跨目录编辑可能写错目录的问题；默认展示全部记录，编辑时锁定真实所属目录。
10. 修复院级工作组 `department_id=null` 时 PostgreSQL 无法推断 UUID 空值类型而返回 500 的问题。
11. 修复并行配置版本迁移后，三级医院数据导入仍引用已删除唯一约束的问题；导入器改为使用 `ACTIVE` 部分唯一索引幂等处理，不覆盖草稿或归档版本。
12. 浏览器验收脚本更新为当前弹窗交互、生产化组织/字典编码和配置生命周期，不再使用会被清理规则过滤的 `ACC-*` 演示编码。

## 2. 中国三级医院环境适配

- 组织数据：三院区、临床科室、医技科室、行政科室、病区和“科室-床号”床位数据；组织树支持展开、收起、自适应高度和滚动。
- 人员数据：医生、护士、药师、检验、影像、病理、医务、病案、信息安全、挂号与科研岗位，姓名采用中文 / 英文双语展示，并包含执业资质和有效期。
- 字典数据：15 类医院基础值集，保留标准来源、有效期和“只停用、不物理删除”的历史语义。
- 主数据：医保诊断、医保手术操作、药品本位码、检验项目/单位和医院科室目录；包含已匹配、待匹配、冲突和院内扩展等真实治理状态。
- 权限与审计：组织/院区作用域、患者关系、用途、紧急访问、职责分离、不可变审计链和事务事件。
- 任务治理：审计链核验、特权角色冲突、执业资质到期、主数据映射、通知/事务事件对账，并注入成功、部分成功、失败与已处置问题的运行历史。

适配依据包括《电子病历应用管理规范（试行）》《电子病历系统功能规范（试行）》、国家医保信息业务编码标准以及卫生健康行业网络安全要求。合成数据用于开发验收，不包含真实患者健康信息。

## 3. 多级页面与真实流程

多级页面按业务对象展开，而不是机械复制空页面：

1. 系统管理一级入口。
2. 十二个管理域二级菜单。
3. 人员/组织/角色/策略/目录/任务清单。
4. 单个业务对象详情。
5. 角色任期、成员、配置版本或任务批次。
6. 审计/治理问题集合。
7. 单条审计事件或处置证据。

已由浏览器自动化验证的七级链路为：人员清单 → 人员档案 → 角色集合 → 角色任期 → 相关审计 → 审计集合 → 单事件。其他管理域按自身业务深度提供版本、审批、引用、运行批次和处置证据，不创建无业务意义的空层级。

## 5. 安全修复与边界

- 管理审计、运行任务、主数据和工作组均在服务端校验有效角色任期，不信任前端菜单可见性。
- 写请求使用幂等键、乐观锁和数据库事务；停用操作保留历史引用，不做物理删除。
- 任务和问题处置保留请求人、执行时间、结果、异常、处置人和审计事件。
- 本地开发登录使用数据库凭据、失败计数、锁定和可撤销会话；生产环境仍必须接入真实 OIDC/统一身份、MFA、密钥托管和医院安全运维体系。
- 当前 Agent 能力是确定性规则引擎，能够真实读取数据库并产生治理问题，但不是医疗大模型。真实 DeepSeek/其他模型的制品、推理引擎、硬件和批准阈值未配置，真实模型红队仍为阻断项。

## 6. 剩余问题与发布判断

本轮不把整个系统标记为生产可发布。全量后端回归 14 项失败分布为：

- `MedicalAgentHarnessApiTest`：9 项；医疗 Agent 队列、租约、工具执行和目录数量断言。
- `TertiaryBusinessConfigurationDatasetImportTest`：2 项；业务配置数据集数量/口径。
- `TertiaryTaskCenterDataImportTest`：1 项；任务中心各二级页面数据导入断言。
- `InpatientAdmissionApiTest`：1 项；会诊独立接收、签署意见与申请方完成链路。
- `SpecialtySupportApiTest`：1 项；缺少证据时的专科支持声明门禁。

这些失败不在系统管理定向测试类，且本轮系统管理门禁均通过，但它们仍阻止“整系统可生产发布”的结论。另有前端主包分包警告和 1 处 Jackson 过时 API 警告属于 P2 工程债。

## 7. 最终结论

系统管理模块已经从只展示 Demo 的页面升级为具备数据库、API、权限、幂等、乐观锁、审计、任务运行和治理处置的可运行实现；本轮覆盖的菜单与关键写链验收通过。

这不等于整个电子病历系统已经达到生产上线条件。生产上线前仍需关闭全量回归 14 项失败，完成真实统一身份、密钥/证书、备份恢复、容量与高可用验证，以及真实模型环境的安全红队和医院侧用户验收。
