## 1. 本轮已完成

### 1.1 配置定义和中国三级医院数据

- 工作流使用结构化节点、边、条件和阻断策略，不再依赖页面内写死的演示列表。
- 表单模板增加术语集、字段约束和医疗数据标准元数据；规则时限使用结构化规则和时限配置；职责范围使用结构化主体、资源和操作范围。
- 数据口径升级为 `tertiary-business-cn-v3`，补充 ICD 国家临床版、WS/T 363、WS 445、电子签名/CA/可信时间戳、最小必要、数据留存等中国医疗约束。
- 能力包和科室适配不再显示写死的演示条目和虚构 A/A+ 评级，改为读取数据库 payload 中的模块目录、发布状态和证据维度。

### 1.2 真实运行时和 Agent

- 新增持久化的配置执行记录，支持流程启动/流转、表单校验、规则评估、职责授权、证据查询、幂等键、审计链和 Outbox。
- 业务配置工作台的运行操作已调用后端 API，不是仅在浏览器内变更状态。
- Agent 增加 `CONFIGURATION` 上下文和 `BUSINESS_CONFIGURATION_READ` 工具，只返回已发布配置并执行脱敏、权限、审计和工具治理。

### 1.3 深层页面

- 补全了模块、配置项、修订记录、运行记录、单次执行、证据和审计的 2–7 级动态路由与详情页。
- 新建、编辑、删除/归档使用对话框；工作流页支持真实节点与连线视图；表格、操作区和对话框补充宽度、间距和溢出约束。

### 1.4 安全修复

- 配置作者与审批人角色分离，作者不能审批自己的配置。
- 配置执行记录持久化组织、院区、患者和就诊上下文；读取、列表、流转和证据查询都按同一上下文过滤，修复了同租户跨院区查看执行数据的风险。
- `PATIENT` / `ENCOUNTER` 主体必须与已授权的患者/就诊上下文匹配；任意主体执行都不允许缺失临床上下文。
- 审计链追加时先锁定租户，避免并发写入破坏哈希链。
- 配置输入、执行输入、输出和幂等键均有长度或大小限制；本轮变更文件的内联凭据模式扫描无命中。

## 4. 未声称完成的生产缺口

1. **全仓 Java/全量迁移未作为本提交门禁。** 共享开发库同时存在其他模块尚未提交的迁移和数据变更；专项测试改用独立临时数据库，并仅补入最新基线导入器必需的任务表迁移作为测试前置，因此 27/27 只代表业务配置专项通过。
2. **未做新的真后端浏览器 E2E。** 前端单测和完整工作区兼容构建通过；本轮没有再跑一次 2–7 级页面的浏览器写入链，沿用此前人工页面核对和 API 专项证据。
3. **通用配置引擎尚未自动拦截所有临床域服务。** 配置可发布、可执行、可被 Agent 读取，临床路径发布也有专用适配；但医嘱、文书、检验等每个现有域服务尚未全部接入通用规则/流程拦截器。
4. **配置定义本身仍是租户级。** 执行数据已做组织/院区/患者/就诊隔离，但 `configuration_item` 尚无组织和院区适用范围字段。如果一个租户承载多院区差异化配置，还需要增加定义层适用性。
5. **外部生产依赖尚未联调。** 真实 CA/时间戳、HIS/LIS/PACS、生产 IdP、真模型与硬件均不在本地合成测试证据中；目前是可配置适配器和仿真数据，不等同于通过了生产认证。

1. 修复 V310 并使全量迁移和 Java 全套件通过。
2. 修复 Mock Interface 合同门禁后恢复 Contracts 4/4。

4. 根据业务优先级将通用配置引擎接入医嘱、文书、检验等域服务，并补充多院区配置适用范围。
5. 在目标医院环境完成外部系统、身份、电子签名、模型和安全渗透联调。
