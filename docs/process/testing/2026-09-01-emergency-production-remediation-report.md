# 急诊工作台生产化整改与复测报告

- 日期：2026-09-01
- 范围：急诊工作台、预检分诊、急诊病历、抢救留观、急诊护理、急会诊与交接，以及 L3–L7 患者纵深页面和急诊 Agent 入口
- 结论：**本地合成数据环境功能回归通过；生产发布 NO-GO**

## 1. 本轮实际完成

| 领域 | 完成内容 | 业务影响 |
|---|---|---|
| 身份与护理 | 新增急诊腕带核验记录、脱敏标识与哈希比对；生命体征写入要求当前急诊就诊 30 分钟内核验成功 | 错腕带、未登记腕带和未核验状态会阻断床旁生命体征写入并留存审计 |
| 会诊与交接 | 建立急诊专用协同单，覆盖急会诊、跨班交接、转运；状态为 `OPEN → ACKNOWLEDGED → COMPLETED` 或逻辑作废 | 指定接收人、接收/完成时间、超时和未完任务真实影响急诊闭环，不再复用住院病区交班假数据 |
| 域切换 | 门诊、急诊、住院三域显式切换；校验源/目标就诊属于同一患者且就诊类型匹配 | 转住院必须引用真实住院就诊，错误切换支持更正版本与逻辑作废 |
| 分诊 | 四级显示改为 I(A)、II(B)、III(C)、IV(D)；“立即处置”不再冒充绿色通道或实际红黄绿分区 | 分诊结果驱动处置优先级，院内时限、分区、危险信号和绿色通道继续要求医院发布规则 |
| 留观 | 删除固定 12 床、固定复评频率、管路/用药/未回结果“已通过”等虚构状态 | 没有真实床位或结构化事实时显示未接入/未通过，不再生成虚假安全结论 |
| 数据隔离 | 急诊列表按当前患者和当前急诊就诊过滤，切换患者后重新签发上下文租约 | 防止同一患者不同就诊或不同患者的流程事实混入当前工作台 |
| L3–L7 | 新增患者全景、跨模块时间线、安全门禁、转运就绪、证据台账 | 从二级页面继续下钻到资源 ID、版本、状态、阻断原因和授权范围 |
| Agent 入口 | 急诊入口携带当前患者、就诊、主 Agent、阶段和目标；输出限定为候选稿并要求人工复核 | 上下文接线完成，但本地无可用模型，不能宣称 Agent 已完成真实推理，见第 4 节 |
| 移动端 | 修复 390px 视口页头快捷按钮遮挡患者卡片 | 修复后 `body/root scrollWidth = 390`，无横向溢出 |

## 2. 中国医疗环境适配依据

- 分诊严重程度语义参考国家卫生健康委 WS/T 390—2012 的 A–D 分级；未把尚未配置的院内时限、分区或绿色通道规则写死在产品中。
- 医疗记录采用事件时间与记录时间分离、更正/作废留痕、原事实不可覆盖。
- 访问控制以岗位、患者/就诊上下文租约和最小必要范围为边界；完整审计仅允许在授权审计中心查询。
- 身份核验仅保存脱敏展示和哈希证据，避免在护理执行页面持久化明文标识。

## 4. 未完成与生产阻塞

以下项目仍是未完成状态，不能表述为“真实医院生产可用”：

1. **Agent 真实运行未完成**：急诊入口和上下文绑定可用，但当前页面显示“暂无可用模型”，发送按钮禁用。必须配置 `ACTIVE + APPROVED + READY` 模型、数据处理授权、独立发布审批，并完成至少 20 例正式评测、临床专家盲审和真实模型安全红队。
2. **真实统一身份未接入**：当前浏览器验收使用开发合成身份。真实 OIDC/MFA、人员主数据、岗位任期、紧急访问再认证和院方账号生命周期尚未联调。
3. **医院规则未配置**：分诊时限、红黄绿分区、危险信号、绿色通道、留观复评频率和转运规则必须由目标医院按已发布制度配置并审批。
4. **外部临床事实未接入**：真实 LIS/PACS、床位主数据、输液泵/监护设备、管路、用药、未回结果、财物和接收科室主数据尚未联调；相关门禁目前失败关闭，不伪造通过。
5. **密码与电子签名基础设施未完成**：生产 KMS/HSM、CA、可信时间戳、密钥轮换、密文备份恢复尚未完成院内验收。
6. **生产非功能验证未完成**：WAF/网关限流、并发压测、容量、HA/灾备、RTO/RPO、等保/密评、第三方渗透测试和医院 UAT 尚无证据。
7. **仓库全量 Java 回归仍受阻**：四个非急诊测试源当前无法编译；全系统发布门禁仍为 NO-GO。
8. **前端性能仍有警告**：主包 546.45 kB，需继续拆分公共依赖和首屏非必要代码。

## 5. 对“二、三、四、五、六、七级等更高页面”的结论

- L2 六个急诊业务入口均有真实 API/数据库流程或明确失败关闭的门禁。
- L3–L7 已补充真实聚合、时间线、门禁、转运就绪和证据台账。
- 没有为追求层级数量继续制造无业务对象的 L8/L9 空页面；更深操作以资源详情、版本、更正、作废、审计证据和 Agent 任务页面承载。若医院实际岗位流程需要 L8+，必须从院方 SOP 和具体业务对象派生后再实现。

## 6. 发布判定

- 本地开发/演示：可用于合成数据功能验证。
- 院内受控试点：当前不满足，至少要关闭第 4 节第 1–5 项并完成院方审批。
- 生产上线：**NO-GO**。
