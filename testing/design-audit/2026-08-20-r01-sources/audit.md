# 病历来源与附件视觉验收

> 日期：2026-08-20  
> 页面：`#/record-sources`  
> 结论：本功能包视觉门禁通过；不据截图声称完整 WCAG 合规。

## 验收步骤与证据

1. 桌面基线：打开已签署文书的来源页，核对一级/二级导航、患者上下文、指标、只读原因、来源链、两类操作和附件对象。基线见 `01-record-sources-desktop.png`。
2. 可读性修正：将本页 9–10px 的关键元数据、字段标签和状态提升到 10–12px，并提高次级文字对比度；为指标、来源链、操作区和附件区补充可访问名称。最终桌面图见 `02-record-sources-desktop-final.png`。
3. 768px 验收：最初发现 Vue 壳仍保留 190px 侧栏，而共享导航已切为横向，导致导航挤在侧栏中；统一 820px 断点后，壳层切为单列、一级导航位于顶部且可横向滚动，AI 助手缩为 44px 圆形入口。最终图见 `04-record-sources-768-final.png`。
4. 结构检查：桌面和 768px 的 `documentElement.scrollWidth` 均等于 `innerWidth`；重复读取页面无 409；已签署文书的上传、来源关联和提交按钮均禁用，并有文本原因，状态不只依赖颜色。

## 严格检查结论

- 信息层级：页面标题 → 病历二级导航 → 患者上下文 → 证据指标 → 只读门禁 → 来源链 → 操作 → 附件对象，顺序稳定。
- 一致性：沿用现有深蓝壳、蓝色主动作、白色证据卡和黄色临床门禁，不新增第二套视觉语言。
- 密度：桌面保持临床工作台紧凑度，但关键标签不再低于 10px；两类证据操作在中等宽度并列，来源链独占一行。
- 响应式：768px 不横溢，一级导航可滚动，主内容占满宽度；未用截图替代交互和 API 验证。
- 边界：本轮未执行屏幕阅读器、色弱模拟器或真实 200% 系统缩放人工测试，因此不宣称完整无障碍认证。
